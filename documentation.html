Documentation Technique - Module Com

Introduction

Le module Com constitue le cœur du middleware de communication pour systèmes distribués. Il fournit une abstraction complète et robuste pour la communication inter-processus, gérant automatiquement l'attribution d'identifiants uniques, les élections de leader, la synchronisation distribuée, et offre des primitives de communication synchrones et asynchrones.

Objectif principal : Simplifier le développement d'applications distribuées en fournissant une couche d'abstraction puissante qui gère automatiquement la complexité des communications distribuées.

Fonctionnalités Clés

  • Communication Messages asynchrones et synchrones
  • Synchronisation Token ring et barrières distribuées
  • Élection Attribution automatique d'IDs
  • Résilience Détection de pannes et réorganisation

Gestion de l'Horloge Logique

L'horloge logique implémente l'algorithme de Lamport pour maintenir un ordre causal entre les événements distribués.

inc_clock()

def inc_clock(self) -> int
Algorithme d'Incrémentation
  1. Incrémente la valeur locale de l'horloge de 1
  2. Garantit un timestamp unique et croissant
  3. Retourne la nouvelle valeur

Cas d'usage : Automatiquement appelé lors de l'envoi de messages, peut être appelé manuellement pour des événements locaux importants.

_update_clock_on_receive()

def _update_clock_on_receive(self, clock) -> int
Algorithme de Lamport
  1. Récupère l'horloge locale actuelle
  2. Récupère le timestamp du message reçu
  3. Calcule : new_clock = max(local_clock, received_clock) + 1
  4. Met à jour l'horloge locale
  5. Retourne la nouvelle valeur

Garantie : L'horloge préserve l'ordre causal des événements et assure la cohérence temporelle distribuée.

Système de Messages Asynchrones

Le système de messages asynchrones utilise une architecture publish-subscribe via PyEventBus3. Les messages sont déposés dans une boîte aux lettres thread-safe.

broadcast()

def broadcast(self, payload)
payload str Contenu du message à diffuser
Mécanisme de Broadcast
  1. Vérifie l'initialisation du processus
  2. Incrémente l'horloge logique locale
  3. Crée un BroadcastMessage avec timestamp
  4. Publie sur PyEventBus (non-bloquant)
  5. Retourne immédiatement

send_to()

def send_to(self, payload, dest)
payload str Contenu du message
dest int ID du processus destinataire

Note : Les messages sont filtrés automatiquement - seul le processus destinataire les traite.

API MailBox - Gestion des Messages

La mailbox est une structure FIFO thread-safe pour stocker et récupérer les messages asynchrones.

Récupération de Messages

get_message()

def get_message(self) -> Message|None

Récupère et retire le premier message de la file (FIFO).

get_messages()

def get_messages(self) -> List[Message]

Récupère et retire tous les messages, vidant complètement la mailbox.

get_message_from()

def get_message_from(self, source) -> Message|None

Récupère le premier message d'une source spécifique.

Filtrage par Type

Méthode Type Supporté Description
get_messages_type("broadcast") BroadcastMessage Messages diffusés à tous
get_messages_type("dedicated") DedicatedMessage Messages point-à-point

Inspection Non-Destructive

def has_messages(self) -> bool

Vérifie la présence de messages sans les retirer de la mailbox.

Communications Synchrones

Les communications synchrones bloquent l'émetteur jusqu'à réception d'un accusé de réception, garantissant que le message a été effectivement reçu et traité.

broadcastSync()

def broadcastSync(self, payload, sender_id)
Protocole Broadcast Synchrone
  1. Crée un BroadcastSyncMessage avec ID unique
  2. Diffuse le message sur PyEventBus
  3. Initialise un compteur d'ACKs (nbProcess - 1)
  4. Entre en attente active des confirmations
  5. Décrémente le compteur pour chaque ACK reçu
  6. Sort quand tous les ACKs sont reçus

sendToSync() / recevFromSync()

def sendToSync(self, payload, dest)
def recevFromSync(self, source) -> str

Utilisation : Ces méthodes doivent être appelées en miroir - un processus appelle sendToSync() pendant qu'un autre appelle recevFromSync().

Émetteur: sendToSync()
→
Message envoyé
→
Récepteur: recevFromSync()
→
ACK automatique
→
Émetteur débloqué

Token Ring et Section Critique

Le système implémente un algorithme de token ring pour garantir l'exclusion mutuelle. Un token unique circule selon une topologie en anneau logique.

Formation de l'Anneau

Topologie Logique
  1. P0 → P1 → P2 → ... → Pn-1 → P0
  2. Chaque processus calcule son suivant : (myId + 1) % nbProcess
  3. Adaptation automatique lors des pannes

États de Section Critique

État SC Signification Comportement
0 Libre Aucune demande, token transféré immédiatement
1 Demandé Attente du token, bloque dans request_SC()
2 Possédé En section critique, accès exclusif garanti

API Section Critique

request_SC()

def request_SC(self)
Demande d'Accès Exclusif
  1. Met SC = 1 (marque la demande)
  2. Log l'intention d'accès
  3. Entre en boucle d'attente : while SC != 2
  4. Retourne quand le token est obtenu (SC = 2)

Attention : Cette méthode est bloquante jusqu'à obtention du token. Garantit l'exclusion mutuelle.

release_SC()

def release_SC(self)
Libération de la Section Critique
  1. Log "Exiting critical section"
  2. Met SC = 0 (marque la libération)
  3. Le handler on_token() détecte SC = 0
  4. Transfert automatique au processus suivant

Exemple d'Utilisation

// Demander l'accès exclusif
com.request_SC()

// Section critique - accès garanti exclusif
critical_resource.modify()
calculate_important_result()

// Libérer pour les autres processus
com.release_SC()

Barrières de Synchronisation

Les barrières permettent à tous les processus de se synchroniser à un point donné. Aucun ne peut continuer tant que tous n'ont pas atteint la barrière.

synchronize()

def synchronize(self)
Protocole de Synchronisation
  1. Incrémente sync_generation (nouvelle barrière)
  2. Met sync_barrier = True
  3. Envoie message "READY" avec génération
  4. Attend que tous les processus soient prêts
  5. Le coordinateur envoie "SYNC_RELEASE"
  6. Tous sortent de l'attente simultanément

Mécanisme des Générations

Problème résolu : Les générations évitent la confusion entre différentes barrières consécutives et préviennent les boucles infinies de synchronisation.

Auto-Jointure Intelligente

Fonctionnalité avancée : Un processus qui reçoit un READY rejoint automatiquement la barrière, permettant à un seul processus d'initier la synchronisation globale.

Système d'Élection et Attribution d'IDs

Le système d'élection permet l'attribution automatique et décentralisée d'identifiants uniques via un algorithme d'élection par comparaison de nombres aléatoires.

request_dynamic_id()

def request_dynamic_id(self)
Algorithme d'Attribution d'ID
  1. Phase 1 : Détection de coordinateur (PING_COORDINATOR)
  2. Phase 2 : Si coordinateur trouvé → demande d'ID
  3. Phase 3 : Si pas de coordinateur → élection
  4. Élection : Tire nombre aléatoire (1-1,000,000)
  5. Collecte : Attend 1.5s pour tous les nombres
  6. Gagnant : Plus grand nombre devient coordinateur

Gestion des Égalités

Départage : En cas d'égalité sur le nombre aléatoire, le processus avec le plus petit temp_id gagne. Si égalité persistante, re-tirage automatique.

Attribution Automatique

Actions du Coordinateur
  1. S'attribue l'ID 0 (coordinateur)
  2. Démarre le système de heartbeat
  3. Assigne les IDs 1, 2, 3... aux participants triés
  4. Diffuse le nombre total de processus
  5. Met à jour le système de détection de pannes

Heartbeat et Détection de Pannes

Le système de heartbeat permet la détection automatique des pannes et la réorganisation dynamique du système distribué.

Mécanisme de Heartbeat

Paramètre Valeur Description
Intervalle d'envoi 2 secondes Fréquence des signaux de vie
Timeout de détection 5 secondes Délai avant détection de panne
Ratio de tolérance 2.5x Marge de sécurité réseau

Réorganisation après Panne

Processus de Réorganisation
  1. Détection : Timeout de 5s sans heartbeat
  2. Classification : Coordinateur vs processus ordinaire
  3. Réorganisation : Combler les trous dans la numérotation
  4. Notification : Messages IdReassignmentMessage
  5. Adaptation : Token ring et barrières mises à jour

Exemple de Réorganisation

Avant panne : P0, P1, P2, P3, P4
↓ P2 tombe en panne ↓
Après réorganisation : P0, P1, P2(ex-P3), P3(ex-P4)

start_heartbeat() / stop_heartbeat()

start_heartbeat() void Démarre l'envoi périodique automatique
stop_heartbeat() void Arrête les signaux (simule une panne)

Gestionnaires d'Événements

Le système utilise PyEventBus3 avec le mode PARALLEL pour le traitement concurrent des événements. Chaque handler est décoré avec @subscribe.

Handlers Principaux

Handler Type d'Événement Fonction
on_broadcast() BroadcastMessage Traite messages diffusés + messages système
on_dedicated() DedicatedMessage Messages point-à-point filtrés par destinataire
on_token() TokenMessage Gestion complète du token ring
on_sync() SyncMessage Messages READY/SYNC_RELEASE des barrières
on_heartbeat() HeartbeatMessage Signaux de vie pour détection de pannes

Filtrage Intelligent

Optimisation : Les handlers filtrent automatiquement les messages propres au processus et séparent les messages système des messages utilisateur.

Mode PARALLEL

Concurrence : Chaque handler s'exécute dans son propre thread, permettant le traitement concurrent. Nécessite une synchronisation appropriée avec mutex.

Cycle de Vie d'un Processus

États du Processus Distribué

Phases du Cycle de Vie

1. Phase d'Initialisation
  1. Génération du temp_id (nombre aléatoire)
  2. Création de l'instance Com
  3. Enregistrement sur PyEventBus
  4. Démarrage du thread processus
2. Phase d'Élection
  1. Recherche de coordinateur existant
  2. Si absent : tirage de nombre aléatoire
  3. Diffusion et collecte des nombres
  4. Détermination du gagnant
3. Phase Opérationnelle
  1. Attribution de l'ID permanent
  2. Démarrage du heartbeat
  3. Participation au token ring
  4. Communications et synchronisations

Gestion des Transitions

Robustesse : Le système gère automatiquement les transitions d'état et peut récupérer des pannes temporaires ou des conditions de course.

Performance et Optimisations

Thread Safety

Composant Mécanisme Protection
MailBox Mutex unique Accès concurrent sécurisé

Exemples d'Utilisation

Application Distribuée Complète

from Process import Process
from time import sleep

class DistributedApplication(Process):
    def run(self):
        # Attribution automatique d'ID
        self.com.request_dynamic_id()

        loop = 0
        while self.alive:
            if loop % 5 == 0:
                self.com.log(f"Loop: {loop}")

            # Communications asynchrones
            if loop == 1:
                self.com.broadcast(f"Hello from P{self.myId}")
                if self.myId > 0:
                    self.com.send_to("Private message", 0)

            # Traitement de la mailbox
            if loop == 2:
                if self.com.has_messages():
                    messages = self.com.get_messages()
                    for msg in messages:
                        self.com.log(f"Received: {msg.get_payload()}")

            # Section critique (mutual exclusion)
            if loop == 3 and self.myId == 1:
                self.com.request_SC()
                self.com.log("Critical section - exclusive access")
                sleep(1)  # Travail critique
                self.com.release_SC()

            # Barrière de synchronisation
            if loop == 5:
                self.com.synchronize()
                self.com.log("All processes synchronized!")

            # Communication synchrone
            if loop == 6 and self.myId == 0:
                self.com.broadcastSync("Sync message from coordinator", 0)

            sleep(1)
            loop += 1

# Utilisation
if __name__ == "__main__":
    processes = []
    for i in range(3):
        name = ["Alice", "Bob", "Charlie"][i]
        processes.append(DistributedApplication(name, 3))

    # Les processus démarrent automatiquement
    sleep(30)  # Laisser tourner 30 secondes

    # Arrêt propre
    for p in processes:
        p.stop()
    for p in processes:
        p.waitStopped()

# Processus producteur
if self.myId == 0:

# Phase de calcul distribué
